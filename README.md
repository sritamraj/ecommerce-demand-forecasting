# E-Commerce Demand Forecasting & Inventory Decision System

An end-to-end data science and ML system that forecasts daily product-level demand, validates models using chronological time-series evaluation, analyzes forecast drivers and errors, and converts forecast uncertainty into an explicit inventory decision policy.

The project demonstrates:

* Data quality validation
* SQL business analysis
* Time-series feature engineering
* Leakage prevention
* Model selection
* Expanding-window cross-validation
* Frozen final-test evaluation
* Forecast-error analysis
* Demand-driver association analysis
* Inventory simulation
* Inventory stress testing
* Inventory sensitivity and cost analysis
* Production model training
* Batch inference
* FastAPI model serving
* Docker containerization
* Automated testing
* Reproducibility auditing

> **Dataset note:** The project uses synthetic retail data deliberately so the complete workflow can be reproduced while keeping assumptions and data-generation logic transparent.

## Project Overview

### Business Problem

Given historical product sales data:

1. How accurately can future product demand be forecast?
2. Which business and calendar variables are associated with demand patterns?
3. Where does forecast error concentrate?
4. How can forecast uncertainty be converted into an inventory policy?
5. How does inventory performance change under demand shocks and capacity constraints?
6. How can the final model be operationalized for batch and API inference?

# Leakage Prevention

Leakage prevention is treated as a first-class modeling requirement.

For a prediction at date `t`, historical demand features only use information available before `t`.

Example:

```text
lag_1 at January 20
        =
demand on January 19
```

Rolling statistics operate on shifted demand:

```python
shifted = quantity.shift(1)
```

Therefore the target day's demand cannot enter its own rolling features.

The pipeline also prevents future business variables from being backfilled into historical observations.

Historical prices are forward-filled only from information already available in time.

Future prices are never used to populate earlier dates.

The final test period is excluded from:

* Model selection
* Feature selection
* Forecast-error uncertainty calibration
* Safety-stock calibration

Regression tests explicitly protect these behaviors.

# Time-Series Validation

Random `train_test_split` is deliberately not used.

The forecasting problem is chronological:

```text
past -> future
```

rather than independently distributed observations.

## Final Holdout


# Key Interview Talking Points

### Why is this a time-series problem?

Observations are ordered in time and future demand must be predicted using information available before the prediction date.

### Why not use random train-test split?

Random splitting can violate chronological structure and allow information from later periods to influence evaluation of earlier periods.

### Why use a Seasonal Naive baseline?

A simple operationally plausible baseline establishes whether additional model complexity improves forecasting performance.

### Why use `lag_7`?

Weekly seasonality makes the previous week's same-day demand a natural predictor for retail demand.

### How was target leakage prevented?

Historical demand features use only prior observations. Rolling features operate on shifted demand, and future business values are never backfilled into earlier observations.

### Why compare multiple models?

Comparing linear, tree-based, ensemble, and simple seasonal approaches helps determine whether nonlinear models provide measurable improvement over simpler alternatives.

### How was the final model selected?

Four expanding-window development folds were used for model assessment. The selected Gradient Boosting configuration was then frozen, retrained on the development period, and evaluated once on the untouched 60-day final test period.

### How was inventory uncertainty calibrated?

Development-period out-of-fold Gradient Boosting predictions were used to estimate forecast-error variability. Final-test residuals were excluded from safety-stock calibration.

### Why is the protection period 10 days?

```text
3-day lead time + 7-day review period = 10-day protection period
```

### What does cycle service level mean?

The percentage of simulated inventory cycles/days without a stockout under the project's simulation definition. It should not be confused with fill rate.

### What does the demand-driver analysis prove?

It identifies associations and predictive patterns in the synthetic dataset. It does not establish causal effects.

### What are the major production assumptions?

* Synthetic data
* Known-at-forecast-time promotion information
* Fixed lead time
* Fixed review period
* Simplified forecast-error scaling
* Frozen-policy inventory evaluation
* Explicit illustrative cost assumptions

These assumptions are documented rather than hidden.

# Limitations

## Synthetic Dataset

The data generator does not reproduce every relationship found in real retail systems.

Not explicitly modeled:

* Product cannibalization
* Cross-product substitution
* Stock-dependent observed demand
* Supplier constraints
* Variable supplier lead times
* Complex promotion planning
* Real purchase-order constraints

## Forecast Model

The project uses:

```text
HistGradientBoostingRegressor
```

It should not be described as XGBoost.

## Inventory Policy

The inventory policy is intentionally simplified.

It does not fully optimize:

* Supplier constraints
* Minimum order quantities
* Multiple warehouses
* Stochastic lead times
* Complex procurement constraints

## Frozen Simulation

The current inventory simulation evaluates a frozen forecast plan over the final 60-day period.

A production system would normally refresh forecasts as new observations arrive.

## Forecast Uncertainty

The current safety-stock calculation uses a simplified forecast-error standard-deviation approach and assumes approximately independent daily errors when scaling uncertainty.

Production extensions could use:

* Quantile forecasting
* Prediction intervals
* Conformal prediction
* Probabilistic forecasting
