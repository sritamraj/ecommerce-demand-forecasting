# Data

All files here are generated by `src/generate_data.py` (raw) and the
notebooks (cleaned/derived). Nothing here is real customer or company
data — see the root README's Limitations section for why synthetic
data was used and how it was built to be realistic.

## `sales_raw.csv`

One row per `(date, product_id)`. Columns:

| Column | Description |
|---|---|
| `date` | Calendar date (some rows intentionally have bad/invalid values — see below) |
| `product_id` | `P001`–`P040` |
| `category` | Electronics / Home & Kitchen / Apparel / Beauty |
| `quantity` | Units sold that day (target variable; some rows intentionally negative/missing) |
| `price` | Unit price after any discount (some rows intentionally missing/negative) |
| `promotion` | 1 if the product was on promotion that day |
| `discount` | Discount % applied (0 if no promotion) |
| `store` | Synthetic store identifier |
| `region` | North / South / East / West |
| `holiday` | 1 if the date is a modeled US holiday |

### Intentionally injected data-quality issues

So notebook `01_data_quality.ipynb` has real problems to find (rather
than a suspiciously perfect file), the raw export contains:

- ~0.4% missing `quantity`, ~0.2% missing `price`
- A handful of duplicated `(date, product_id)` rows
- A handful of negative `quantity` and negative `price` values
  (data-entry-style errors)
- A handful of invalid/out-of-range `date` values (a future-dated typo
  and an unparseable text date)

All of these are found, quantified, and resolved in notebook 01, and
the decisions made (drop vs. correct vs. flag) are documented inline
there.

## `sales_clean.csv`

Output of notebook 01: bad rows removed/corrected, `date` parsed to a
proper datetime, duplicates dropped. Everything downstream reads this
file, not the raw one.

## `model_features.csv`

Output of notebook 03: `sales_clean.csv` plus lag features
(`lag_1/7/14/28`), rolling statistics (`rolling_mean/std_7/14/28`), and
calendar features (`day_of_week`, `month`, `week_of_year`,
`is_weekend`). Rows at the start of each product's history that don't
have enough prior data for the longest lag/rolling window are dropped
(not filled with fabricated values).

## `test_predictions.csv`

Every model's predictions on the final 60-day chronological holdout,
alongside the actual `quantity` — used by notebooks 04–06 for
evaluation, error analysis, and the inventory simulation.
